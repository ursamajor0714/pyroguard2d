# [SYSTEM INSTRUCTION & DEVELOPMENT RULES]

## 1. 개발 및 코딩 원칙 (Web/JS 특화)
- **룰 최우선 준수 (RULES.txt)**: 모든 작업 시 반드시 이 파일(`RULES.txt`)의 지침을 최우선으로 정독 및 적용한 후 코딩할 것.
- **오답 노트 기록 및 재발 방지**: 과거 오류나 잘못된 수정 패턴은 본 `RULES.txt` 파일 하단에 즉시 기록하고, 오류 수정 요청 시 이를 반드시 선행 참고하여 동일 실수 반복 금지.
- **생각 선행 (Chain of Thought)**: 복잡한 코드 작성 전, 한 줄 주석으로 작동 원리와 로직 흐름(Pseudocode)을 먼저 설계할 것.
- **과잉 구현 금지 (YAGNI)**: 명시적으로 요청한 요구사항만 구현. 추측 코딩 및 미요청 기능 선구현 절대 금지.
- **UI 및 레이아웃 보존**: 수정/추가 시 기존 HTML 태그 구조, CSS 클래스명, ID를 절대 임의 삭제/변경 금지 (화면 붕괴 방지).
- **태그 무결성 강제**: HTML 닫는 태그 및 괄호 누락으로 인한 렌더링/문법 오류가 발생하지 않도록 철저히 검증할 것.
- **기능 무손실 리팩토링**: 기존 정상 작동 로직 및 예외 처리를 절대 누락하거나 임의 삭제 금지.
- **최소한의 변경 (Minimal Change)**: 목표 기능 구현에 필요한 최소한의 라인만 정확히 수정할 것.
- **조기 리턴 (Early Return)**: 복잡한 if-else 중첩 금지. 함수 최상단에서 예외를 처리하고 리턴(Guard Clauses).
- **가정 금지 (No Assumptions)**: 모호한 부분은 넘겨짚지 말고, 필요한 파일 검색 후 단답으로 질문할 것.
- **거짓 성공 보고 금지**: 실제 작동 여부 검증 없이 임의로 '수정 완료' 단정 짓지 말 것.
- **순수 함수 및 로직 분리**: UI(DOM) 조작과 데이터 계산 로직을 분리하여 부수 효과를 최소화할 것.
- **이벤트 과부하 방지**: 잦은 호출이 일어나는 이벤트(scroll, resize 등)는 Debounce/Throttle 필수 적용.
- **명명 규칙 강제**: 변수/함수 `camelCase`, 상수 `UPPER_SNAKE_CASE`, 클래스/컴포넌트 `PascalCase` 통일.
- **타입 힌트 (JSDoc)**: 복잡한 함수나 객체의 파라미터/반환값은 JSDoc으로 타입을 명시할 것.
- **디버깅 코드 금지**: 최종 코드에 `console.log`, `debugger` 등 테스트용 잔여 코드 절대 남기지 말 것.
- **보안 및 접근성**: 사용자 입력 취급 시 XSS 방지 적용, 상호작용 요소는 웹 접근성(a11y) 준수. HTTPS 연결 강제화 및 공통 전/후처리를 위한 미들웨어 구조 설계 필수 (단, 로컬 개발 환경 예외 처리 및 혼합 콘텐츠 에러 방지 대책 포함).
- **HTML/JS 표준**: 시맨틱 태그 필수, JS 로딩 제어(defer/async), 인라인 스크립트 작성 금지.
- **중복 로직 모듈화**: 3회 이상 반복 로직/함수는 공통 파일/훅으로 분리하여 재사용.
- **전역 오염 방지**: `const`, `let` 필수. 전역 변수 생성 최소화(단일 네임스페이스 활용).
- **안전한 DOM/에러 처리**: DOM 탐색 실패 대비 예외 처리 필수, 외부 API 호출 시 Fallback 제공.
- **자원 해제 필수**: 이벤트 리스너, 타이머 등 자원은 사용 완료 시 명시적 해제 처리할 것.
- **의존성/하드코딩**: 매직 넘버 금지(상수화), 민감 데이터 `.env` 관리.

## 2. 응답 및 출력 포맷
- **인사/잡담 금지**: 서론/결론 생략, 바로 결과만 출력. (Caveman Speak: 명사 위주 단답형)
- **코드 중심**: 줄 단위 설명 금지. 수정된 코드 블록과 핵심 주석 한 줄만 제공.
- **질문 최소화**: 추가 정보 필수 상황 외 질문 금지.
