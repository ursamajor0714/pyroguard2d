  프로젝트명: PyroGuard 2D (파이로가드 2D 소방 관제 시스템)
  문서 목적: 프로젝트 내 구현된 API 엔드포인트 기능, 요청/응답 규격, 비즈니스 로직 총정리
  갱신일자: 2026-09-26 (27차 패치 — 인증·119 승인 범위·입력 검증·영속 저장)


================================================================================
  1. API 엔드포인트 개요 (요약표)
================================================================================

  | 엔드포인트 | 메서드 | 로그인 | 주요 기능 | 설명 및 비즈니스 로직 |
  |---|---|---|---|---|
  | /api/auth/login | POST | 불필요 | 운영자 로그인 | OPERATOR_PASSWORD 검증 → HttpOnly 세션 쿠키 + token 반환. 같은 IP 5회 연속 실패 시 5분 잠금 |
  | /api/auth/logout | POST | 불필요 | 로그아웃 | 세션 쿠키 삭제 + 이 단말의 119 승인 해제 |
  | /api/auth/session | GET | 불필요 | 로그인 여부 | { authenticated, expiresAt } |
  | /api/health | GET | 불필요 | 상태 확인 | 외부 업타임 감시용. 설정(인증·OTP)·저장소 쓰기 가능 여부만 반환, 데이터 없음 |
  | /api/sensors | GET | 필요 | 센서 목록 조회 | 전체 또는 특정 층. ETag 지원(변경 없으면 304) |
  | /api/sensors | POST | 필요 | 신규 센서 배치 | 입력 검증, 같은 id 가 있으면 409 (덮어쓰지 않음) |
  | /api/sensors | PUT | 필요 | 센서 상태/위치 수정 | 허용 필드만 부분 수정, expectedUpdatedAt 으로 낙관적 잠금, B2 화재 자동 전환 신호 |
  | /api/sensors | DELETE | 필요 | 센서 철거 | 없는 센서면 404 |
  | /api/floors | GET | 필요 | 층별 현황 집계 | 22개 관제 구역 대표 상태 (ALARM > OFFLINE > MAINTENANCE > NORMAL, 센서 0개면 UNMONITORED) |
  | /api/emergency | GET | 필요 | 119 인명 정보 조회 | 이 단말이 승인된 경우에만 재실자 목록·인원수 반환 |
  | /api/emergency | POST | 필요 | 119 OTP 인증 및 해제 | EMERGENCY_OTP 검증 (경보 중일 때만, 5회 오답 시 잠금) 또는 REVOKE |

  • 인증: 로그인하면 세션 토큰이 HttpOnly 쿠키(pg_session)로 저장된다. 화면이 아닌 클라이언트는
    같은 토큰을 `Authorization: Bearer <token>` 으로 보내도 된다. 로그인 없이 부르면 401.
  • CORS: 같은 출처만 허용. 다른 출처에서 부르려면 CORS_ALLOWED_ORIGINS 에 주소를 적는다.
  • 공통 오류: 깨진 JSON·객체가 아닌 본문 400, 본문 16KB 초과 413, 처리 중 예외 500 (서버 로그에 기록).


================================================================================
  2. 상세 API 명세 및 비즈니스 로직
================================================================================

--------------------------------------------------------------------------------
  [API 1] GET /api/sensors — 센서 목록 조회
--------------------------------------------------------------------------------
  • 기능: 도면에 배치된 전체 또는 특정 층의 센서 노드 목록을 조회합니다.
  • 호출 위치: app/page.tsx, app/mobile-demo/page.tsx (둘 다 SENSOR_POLL_MS = 3초 폴링)
  • 쿼리 파라미터:
    - floorId (선택, string): 특정 층 식별자 (예: 'B2', '1F', 'ROOF'). 없는 층이면 400.
  • 응답 헤더: ETag — 다음 요청에 If-None-Match 로 보내면 변경이 없을 때 304 (본문 없음).
  • 응답 예시:
    {
      "success": true,
      "data": [
        {
          "id": "sensor-1f-cctv-1",
          "type": "CCTV",
          "floorId": "1F",
          "x": 50,
          "y": 85,
          "status": "NORMAL",
          "fov": { "distance": 22, "angle": 90, "rotation": 270 },
          "updatedAt": "2026-09-26T06:00:00.000Z"
        }
      ]
    }


--------------------------------------------------------------------------------
  [API 2] POST /api/sensors — 신규 센서 노드 배치 등록
--------------------------------------------------------------------------------
  • 기능: 도면 위 팔레트 드래그 앤 드롭 또는 모달을 통한 신규 센서를 등록합니다.
  • 호출 위치: store/useSensorStore.ts (addNode), mobile-demo/page.tsx
  • 요청 본문 (JSON) — 규칙: lib/server/validation.ts
    - id (필수, string): 영문·숫자·-·_ 1~80자
    - type (필수): EXTINGUISHER | HYDRANT | WATER_PRESSURE | ARC | LEAK | EMERGENCY_DOOR | CCTV | CUSTOM
    - floorId (필수): 22개 관제 구역 중 하나 (types/floor.ts)
    - x, y (필수, number): 캔버스 퍼센트 좌표 (0~100)
    - status (필수): NORMAL | MAINTENANCE | ALARM | OFFLINE
    - 선택: name(100자 이하), fov{distance 1~100, angle 1~360, rotation 0~360}, doorState, powerStatus, autoCloseDelay(0~600초), value(0 이상), customEmoji
    - 그 밖의 필드는 저장하지 않는다. updatedAt 은 서버가 찍는다.
  • 응답: 201 { "success": true, "data": { …저장된 센서 } } / 400 { errors: [...] } / 409 같은 id 존재


--------------------------------------------------------------------------------
  [API 3] PUT /api/sensors — 센서 정보 & 상태 갱신
--------------------------------------------------------------------------------
  • 기능: 센서 좌표 이동, 경보 발령/해제, 수압/아크 값 변경, 비상문 개폐 제어를 반영합니다.
  • 요청 본문: { id, …바꿀 필드, expectedUpdatedAt? }
    - expectedUpdatedAt 을 보내면 그 사이 다른 단말이 먼저 고쳤을 때 409 (최신 값을 data 로 돌려준다)
  • 비상문 fail-safe: 전원(powerStatus)이 OFF 가 되면 잠금이 자동으로 UNLOCKED 로 바뀐다.
    전원 OFF 인 문을 LOCKED 로 저장하라는 요청은 400.
  • 응답: 200 { success, data: 저장된 센서 } / 400 / 404 없는 센서 / 409 낡은 수정
  • 특수 비즈니스 로직 (B2 화재 트리거):
    - id가 'sensor-ev-smoke'이고 status가 'ALARM'으로 갱신되면 `triggerAutoFloorChange: 'B2'` 반환
    - 화면(store/useSensorStore.ts)이 이 신호를 받아 도면을 B2 로 전환한다.


--------------------------------------------------------------------------------
  [API 4] DELETE /api/sensors — 센서 노드 철거 (삭제)
--------------------------------------------------------------------------------
  • 기능: 도면 밖으로 드래그하거나 모달에서 삭제 시 해당 센서를 제거합니다.
  • 쿼리 파라미터: id (필수, string). 없는 센서면 404.


--------------------------------------------------------------------------------
  [API 5] GET /api/floors — 층별 소방 현황 집계
--------------------------------------------------------------------------------
  • 기능: 22개 관제 구역(외부·옥상·17F~1F·B1~B3)의 센서 수, 경보 여부, 대표 상태를 반환합니다.
  • 상태 집계 우선순위 (lib/floorStatus.ts): ALARM > OFFLINE > MAINTENANCE > NORMAL
    - 센서가 하나도 없는 층은 UNMONITORED (감시 공백을 '정상' 으로 보이지 않게)


--------------------------------------------------------------------------------
  [API 6] GET /api/emergency — 119 인명 정보 조회
--------------------------------------------------------------------------------
  • 기능: 이 단말(세션)의 119 승인 상태를 확인하고, 승인된 경우에만 재실자 목록을 반환합니다.
  • 개인정보보호법 제15조 반영 로직:
    - 미승인: { "success": true, "approved": false, "peopleCount": 0 }
    - 승인:   { "success": true, "approved": true, "expiresAt": "…", "peopleCount": 322, "occupants": [ { id, floorId, x, y, roomName } … ] }
  • 재실자 데이터는 서버 전용 모듈(lib/server/occupants.ts)에만 있고 화면 번들에는 들어가지 않는다.
  • 화면은 이 API 를 3초마다 불러 승인 상태를 맞춘다 — 다른 단말의 상황 종료·유효시간 만료가 바로 반영된다.


--------------------------------------------------------------------------------
  [API 7] POST /api/emergency — 119 OTP 인증 및 권한 해제
--------------------------------------------------------------------------------
  • { "otp": "<6자리>" } — 환경변수 EMERGENCY_OTP 와 비교
    - 형식이 틀리면 400, 틀리면 401 (정답을 알려 주지 않는다)
    - 같은 세션이 5번 연속 틀리면 5분 동안 429
    - 화재 경보(ALARM)가 하나도 없는 평시에는 409 — 인명 정보를 열지 않는다
    - 맞으면 이 세션만 APPROVAL_TTL_MINUTES(기본 30분) 동안 승인
  • { "action": "REVOKE" } — 이 단말의 승인 해제 (119 상황 종료)
  • 모든 승인·실패·해제는 감사 로그(DATA_DIR/audit.log)에 남는다. 재실자 위치 자체는 기록하지 않는다.
