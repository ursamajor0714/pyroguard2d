================================================================================
  1. API 엔드포인트 개요 (요약표)
================================================================================

  | 엔드포인트 | 메서드 | 주요 기능 | 설명 및 비즈니스 로직 |
  |---|---|---|---|
  | /api/sensors | GET | 센서 목록 조회 | 전체 또는 특정 층의 배치 센서 데이터 반환 |
  | /api/sensors | POST | 신규 센서 배치 | 캔버스 도면 위에 신규 센서 노드 등록 |
  | /api/sensors | PUT | 센서 상태/위치 수정 | 센서 상태(경보 등), 좌표, 수압, FOV, 비상문 제어 + B2 화재 감지 트리거 |
  | /api/sensors | DELETE | 센서 철거 | ID 기반 도면 배치 센서 삭제 |
  | /api/floors | GET | 층별 현황 집계 | 20개 층 종합 상태(ALARM > OFFLINE > MAINTENANCE > NORMAL) 및 센서 수 집계 |
  | /api/emergency | GET | 119 인명 정보 조회 | OTP 인증 승인 여부 검증 및 인원 정보 반환 (미승인 시 개인정보 차단) |
  | /api/emergency | POST | 119 OTP 인증 및 해제 | OTP('119119') 검증 승인 또는 상황 종료('REVOKE') 세션 해제 |


================================================================================
  2. 상세 API 명세 및 비즈니스 로직
================================================================================

--------------------------------------------------------------------------------
  [API 1] GET /api/sensors — 센서 목록 조회
--------------------------------------------------------------------------------
  • 기능: 도면에 배치된 전체 또는 특정 층의 센서 노드 목록을 조회합니다.
  • 호출 위치: app/page.tsx (3초 폴링), mobile-demo/page.tsx (5초 폴링)
  • 쿼리 파라미터:
    - floorId (선택, string): 특정 층 식별자 (예: 'B2', '1F', 'ROOF' 등). 미지정 시 전체 조회.
  • 백엔드 처리 로직:
    - 인메모리 방재 데이터베이스 조회 및 층별 필터링.
  • 응답 예시:
    {
      "success": true,
      "data": [
        {
          "id": "sensor-cctv-1F-01",
          "type": "CCTV",
          "floorId": "1F",
          "x": 45.2,
          "y": 30.1,
          "status": "NORMAL",
          "fov": { "distance": 12, "angle": 95, "rotation": 90 }
        }
      ]
    }


--------------------------------------------------------------------------------
  [API 2] POST /api/sensors — 신규 센서 노드 배치 등록
--------------------------------------------------------------------------------
  • 기능: 도면 위 팔레트 드래그 앤 드롭 또는 모달을 통한 신규 센서를 등록합니다.
  • 호출 위치: store/useSensorStore.ts (addNode), mobile-demo/page.tsx
  • 요청 본문 (JSON):
    - id (필수, string): 센서 고유 ID
    - type (필수, string): 센서 종류
    - floorId (필수, string): 배치 층 ID
    - x, y (필수, number): 캔버스 퍼센트 좌표 (0~100)
    - status (필수, string): 상태 ('NORMAL'|'MAINTENANCE'|'ALARM'|'OFFLINE')
  • 응답 예시:
    { "success": true, "message": "센서 노드가 정상 등록되었습니다." }


--------------------------------------------------------------------------------
  [API 3] PUT /api/sensors — 센서 정보 & 상태 갱신
--------------------------------------------------------------------------------
  • 기능: 센서 좌표 이동, 경보 발령/해제, 수압/아크 값 변경, 비상문 개폐 제어를 반영합니다.
  • 호출 위치: store/useSensorStore.ts
  • 특수 비즈니스 로직 (B2 화재 트리거 시뮬레이션):
    - id가 'sensor-ev-smoke'이고 status가 'ALARM'으로 갱신되면, `triggerAutoFloorChange: 'B2'` 필드 반환.


--------------------------------------------------------------------------------
  [API 4] DELETE /api/sensors — 센서 노드 철거 (삭제)
--------------------------------------------------------------------------------
  • 기능: 도면 밖으로 드래그하거나 모달에서 삭제 시 해당 센서를 제거합니다.
  • 쿼리 파라미터: id (필수, string)


--------------------------------------------------------------------------------
  [API 5] GET /api/floors — 층별 소방 현황 집계
--------------------------------------------------------------------------------
  • 기능: 빌딩 전체 20개 층을 순회하며 센서 수, 경보 발생 여부, 종합 대표 상태를 반환합니다.
  • 상태 집계 우선순위 로직: ALARM > OFFLINE > MAINTENANCE > NORMAL


--------------------------------------------------------------------------------
  [API 6] GET /api/emergency — 119 인명 정보 조회
--------------------------------------------------------------------------------
  • 기능: 119 소방관 인증 상태를 확인하고, 승인 시 인원수를 반환합니다.
  • 개인정보보호법 제15조 반영 로직:
    - OTP 미승인 상태: { "success": true, "approved": false, "peopleCount": 0 }
    - OTP 승인 상태: { "success": true, "approved": true, "peopleCount": 286 }


--------------------------------------------------------------------------------
  [API 7] POST /api/emergency — 119 OTP 인증 및 권한 해제
--------------------------------------------------------------------------------
  • 기능: 119 전용 OTP('119119') 검증 승인 또는 상황 종료('REVOKE') 세션 해제를 수행합니다.
