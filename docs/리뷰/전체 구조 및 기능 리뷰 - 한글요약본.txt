PyroGuard 2D 소방 방재 관제 시스템 — 프로젝트 종합 요약서

1. 시스템 개요 및 아키텍처

1.1 시스템 개요
• 프로젝트명: PyroGuard 2D (2D CAD 기반 소방 방재 관제 시스템)
• 핵심 목적: 오피스 빌딩 20개 층의 소방 센서, CCTV, 비상문 상태를 2D CAD 도면 위에서 실시간 관제하고 119 긴급 상황 시 인명 위치 정보를 연동하는 방재 시스템입니다.
• 시스템 규모: 지상 17층, 지하 3층, 건물 외부 등 총 21개 관제 구역, 164개 소방 노드, 6종 관제 모달, 7개 백엔드 API, 5개 전역 스토어.

1.2 핵심 기술 스택
• 핵심 프레임워크: Next.js 16.2 (App Router 기반 프론트엔드 및 백엔드 API 통합)
• UI 엔진: React 19.2 (가상 DOM 최소 갱신 및 컴포넌트 단위 관리)
• 언어 및 타입: TypeScript 5 (강력한 정적 타입 추론으로 런타임 오류 방지)
• 전역 상태 관리: Zustand (5개 스토어로 도메인별 리렌더링 분리)
• 2D 캔버스 수학: D3-Zoom / D3-Selection (viewBox 기반 0.5x~5.0x 줌/팬 연동)
• 스트리밍 연동: iframe / hls.js (IP 카메라 및 모바일 카메라 라이브 피드 연동)
• UI 애니메이션: Framer Motion (모달 팝업 및 화면 전환 효과)

1.3 시스템 특징
• 외부 클라우드나 외부 AI 의존성 없는 순수 로컬 초고속 인메모리 데이터베이스 탑재
• SVG 좌표 역변환(getScreenCTM)을 통한 센서 노드 드래그 앤 드롭 자유 배치
• Tailscale 및 DroidCam 호환 iframe 기반 CCTV 라이브 피드 및 90도 회전, 전체화면 조율
• 개인정보보호법 준수를 위한 평시 인명 위치 완전 마스킹 및 119 OTP 승인 후 인명 해독


2. 주요 관제 기능 및 도메인 로직

2.1 2D CAD 평면 도면 관제 (FloorCanvas)
• 1200x800 SVG 좌표계 기반으로 소화기, 옥내소화전, 아크차단기, CCTV, 비상구, 수압계 노드 표출
• 더블클릭 줌 차단 및 층 변경 시 중앙 고정(scale 1.0) 자동 리셋

2.2 2.5D 건물 수직 조감도 관제 (BUILDING View)
• CSS perspective 및 rotate 삼차원 효과로 21개 층의 경보 상태를 한눈에 조망
• 119 OTP 승인 시 빌딩 총 잔류 인원(286명) 및 층별 인원 카드 전면 표출

2.3 CCTV 감시 시야각(FOV) 및 라이브 비디오월
• 삼각함수(cos/sin) 기반 부채꼴 시야각 렌더링 및 거리(1m), 화각(15도), 회전(45도) 스냅 조작
• 2x2, 3x3, 4x4 다채널 비디오월 모달 및 단일 CCTV 회전(0도, 90도, 180도, 270도) 보정

2.4 119 긴급 상황 OTP 인증 및 인명 관제
• 6자리 OTP('119119') 검증 승인 시 인명 정보 위치 표출 및 층별 구조 완료(클리어) 처리
• 상황 종료(REVOKE) 클릭 시 즉시 개인정보 마스킹 재적용 및 초음파 부저 음소거

2.5 B2 EV 충전기 및 소방점검 이력 관리
• B2 지하주차장 전기차 충전기 15대 상태(충전중, 대기, 점검, 폐기) 요약 및 CRUD
• 소방점검 이력(합격, 경고, 불합격) 다중 필터 검색 및 이력 작성


3. 백엔드 API 명세 요약 (7종 REST API)

• GET /api/sensors: 전 전 층 또는 특정 층의 센서 노드 목록 조회
• POST /api/sensors: 도면 위 신규 센서 노드 드래그 앤 드롭 배치 등록
• PUT /api/sensors: 센서 좌표 이동, 경보 발령, 수압/아크 값 변경 (B2 화재 자동 이동 트리거 연동)
• DELETE /api/sensors: 도면 외곽 드롭 시 센서 노드 철거
• GET /api/floors: 20개 층 대표 상태(경보 > 오프라인 > 점검 > 정상) 집계
• GET /api/emergency: 119 OTP 승인 상태 검증 및 인원 정보 반환
• POST /api/emergency: 119 OTP 승인 처리 및 상황 종료 세션 해제


4. 전역 상태 관리 (Zustand 5대 스토어)

• useCanvasStore: 뷰 모드(BUILDING/CANVAS), 선택 층, 줌 배율, 활성 모달 관리
• useSensorStore: 164개 센서 데이터 CRUD 및 활성 경보 수 집계
• useOccupantStore: 119 인명 구조 완료 목록 및 층별 클리어 상태 관리
• useEvChargerStore: B2 EV 충전기 15대 상태 CRUD
• useFireLogStore: 소방점검 이력 로그 CRUD 및 필터링


5. 핵심 리뷰 및 면접 질문 대비 15선

질문 1. Next.js App Router를 채택한 아키텍처적 이유는?
답변: 프론트엔드 UI와 백엔드 REST API를 하나의 프로젝트에서 처리하여 데이터 연동 효율을 높이고, 정적 요소와 동적 인터랙션 컴포넌트를 분리하여 번들 용량을 절감하기 위함입니다.

질문 2. 외부 DB 대신 로컬 인메모리 DB를 구축한 이유는?
답변: 외부 클라우드 지연이나 DB 연결 실패 위험 없이 0ms 초고속 응답을 보장하고 서버 실행 즉시 21개 관제 구역의 데이터를 완벽하게 시연하기 위함입니다.

질문 3. SVG 캔버스가 확대된 상태에서 센서 드래그 좌표는 어떻게 계산하나요?
답변: SVG 컨테이너 요소의 getScreenCTM().inverse() 역행렬 변환 API를 사용하여 마우스의 화면 좌표를 1200x800 도면 내부 좌표로 정확히 역변환합니다.

질문 4. 왜 Redux 대신 Zustand를 상태 관리 라이브러리로 선택했나요?
답변: 보일러플레이트 코드가 90% 이상 적고, 1KB 미만의 초경량이며, 5개 스토어로 도메인을 분리하여 컴포넌트 리렌더링을 효과적으로 격리할 수 있기 때문입니다.

질문 5. CCTV FOV 부채꼴 영역은 어떻게 생성하나요?
답변: 삼각함수(cos, sin)를 이용하여 카메라 위치, 감시 거리, 화각, 회전각을 기반으로 SVG 경로(path d) 부채꼴 호를 동적으로 생성합니다.

질문 6. 센서 노드 상태 갱신 시 B2 화재 자동 이동은 어떻게 동작하나요?
답변: 센서 갱신 API(PUT /api/sensors) 호출 시 B2층 연기 감지기가 ALARM 상태가 되면 백엔드가 응답에 B2 자동 이동 응답을 실어 보내 프론트엔드가 즉시 B2층 도면으로 전환되게 합니다.

질문 7. 개인정보보호법 준수를 위해 인명 정보를 어떻게 처리했나요?
답변: 평시(OTP 미승인)에는 API와 UI 모두 인명 위치 데이터를 완전 마스킹하여 은폐하고, 119 OTP 승인 시에만 적법 목적에 한해 위치 정보를 해독 및 표출합니다.

질문 8. 119 OTP 인증 상황 종료 시 어떤 처리가 일어나요?
답변: POST /api/emergency에 REVOKE 액션을 전송하여 세션을 해제하고, Zustand 스토어의 구조 인원 데이터를 리셋하여 개인정보 재마스킹 상태로 복귀시킵니다.

질문 9. CCTV 카메라 스마트폰 피드의 가로/세로 화면 비틀림은 어떻게 해결했나요?
답변: CctvLiveModal에 90도 회전 버튼을 탑재하여 CSS transform: rotate(90deg) scale(1.35) 트랜지션으로 비율 확장을 보정했습니다.

질문 10. 센서 노드가 3초마다 폴링될 때 성능 저하가 없는 이유는?
답변: React 가상 DOM의 비교(Diffing) 알고리즘이 변경된 노드만 최소 업데이트하고, Zustand 훅이 필요한 데이터 필드만 선택적으로 구독하기 때문입니다.

질문 11. 도면 캔버스 확대 시 노드와 텍스트의 크기 비틀림 방지법은?
답변: SVG viewBox="0 0 1200 800" 고정 비율과 preserveAspectRatio="xMidYMid meet" 설정을 통해 비율을 유지합니다.

질문 12. 웹 브라우저 경보음 합성은 어떻게 구현했나요?
답변: Web Audio API(AudioContext)를 이용하여 800Hz 사인파 펄스를 0ms 지연 없이 브라우저에서 직접 합성 재생합니다.

질문 13. 비상문 자동개폐기의 4단계 상태 구분 기준은?
답변: 소방법 규격에 따라 LOCKED(잠금), UNLOCKED(해제), OPENED(비상 개방), CLOSED(닫힘) 4단계 상태와 자동 닫힘 타이머를 시각화했습니다.

질문 14. 소화기 내용연수 10년 법령을 어떻게 반영했나요?
답변: IoT 센서의 점검 주기를 10년 케어로 동기화하여 점검 상태(MAINTENANCE)로 자동 관리되도록 처리했습니다.

질문 15. 모바일 시연 컨트롤러(/mobile-demo)의 역할은?
답변: 현장 소방점검관이나 시연자가 지하 주차장 연기 감지기 작동 및 비상 경보 발령을 모바일 화면에서 원터치로 테스트할 수 있도록 제공되는 컨트롤러입니다.
